SwiftMiner 1.35

Version 1.35 · Unreleased

Twitch drop claims were landing but being recorded as failures, so claim history, counters and notifications all stayed empty. This release fixes the claim path end to end and rebuilds the Miners tab around a macOS Tahoe operator view.

🎁 Drop Claiming Restored

Claims were reaching Twitch and succeeding, but the response was misread as a failure — so nothing downstream of a claim ever ran.

  • Reads Twitch's current claimDropRewards mutation response, while still accepting the legacy claim field so a mixed rollout cannot break claiming again.
  • Treats Twitch's real success status, and an instance a previous attempt already claimed, as completed — making repeated claim attempts safely idempotent.
  • Confirms an unreported claim across several spaced inventory reads instead of one immediate read, which reported "not claimed" for claims that had in fact landed.
  • Surfaces GraphQL messages, explicit empty payloads and unexpected response keys in diagnostics, so a future Twitch response change is actionable rather than silent.
  • Restores everything that depends on a recorded claim: claim counters, the earning ledger, claim notifications, Discord claim events and Twitch inbox cleanup.
  • Adds regression coverage for current, legacy, already-claimed, malformed and GraphQL-error claim responses, built from real Twitch payloads rather than from the parser.

📊 Claim History Recorded

Claimed rewards are now persisted, so claim statistics report real numbers.

  • Every claim is written to the reward ledger. Nothing had ever written it, so Discord's "claims today" and "drops claimed this week" always reported zero regardless of how much had been claimed.
  • Ledger entries are recorded per account, since a Twitch benefit identifies a reward rather than a reward per user — without this, a second account's claim of the same reward was discarded and its totals came out short.
  • Re-recording a reward is a no-op, so claim retries cannot inflate the totals.

⛏️ Miners Rebuilt for macOS Tahoe

Each miner is now an operator view: who it is, whether it is healthy, and what it is working on next.

  • Rebuilds the selected miner around an identity and live-health header, a Now → Next → Then summary, a resolved campaign queue, compact subsystem checks and priority controls, with recovery history kept secondary.
  • Adopts Tahoe grouped surfaces with larger concentric corners, sentence-case section headers, roomier spacing and a plain source list with a soft selection pill.
  • Groups uptime, last poll and the miner's actual health verdict into equal-width header cells that stay aligned as values change length.
  • Health now reports the miner's condition rather than repeating which campaign it is watching, and its checks align into fixed columns without duplicated claim or status summaries.
  • Shows the linked Discord account avatar in the miner header when one is available, falling back to a local initial.
  • Sizes the current and upcoming campaign artwork consistently, tall enough that the detail beside it fits within the artwork.

🎯 Clearer Drops and Status

Prioritised games stay visible, and status text reflects what is actually happening.

  • A prioritised game now stays in the Drops feed for its whole run instead of disappearing once its rewards are all claimed, which read as the game going missing.
  • "Campaigns in motion" counts campaigns a miner is actually watching, so a campaign one account has finished is still counted while another account mines it.
  • Launch-time campaign and progress refreshes display Updating with a refresh symbol instead of prematurely reporting Up to Date.
  • Miner progress shows verified watched minutes out of required minutes across every timed drop in a campaign, independent of channel or session.
  • Unlinked, non-prioritised campaigns are no longer presented as mineable.
  • Prioritised artwork stays visually stable when returning to Overview instead of replaying its placeholder crossfade.

⚡ Reliability and Performance

Smoother scrolling on the Miners tab, and fewer wasted requests.

  • Direct Twitch watch beacons include the stream category, client timestamp, live-state and watched-minute fields required for drop progress to be credited.
  • Removes a translucent backdrop from the scrolling miner header that was resampled every frame, and builds off-screen detail sections lazily.
  • Resolves each source-row activity snapshot once per render instead of repeating the same work for every field that reads it.
  • Refreshes the minute-level uptime display every 30 seconds rather than every second.
  • Only requests Discord display names when a miner is actually linked, and no longer lets an unreachable SwiftBot stall opening the Miners tab.
  • Adds regression coverage for campaign ordering, cumulative progress, eligibility filtering, startup status and beacon payload parity.
