# Native share invitations

SwiftMiner shares friend setup invitations with SwiftUI's native `ShareLink`. The primary shared item is the HTTPS invitation URL. `subject` and `message` provide the short email title and security context to destinations that support those fields. This keeps the standard macOS share sheet and lets each destination decide how to present the URL.

## Tahoe capability check

The implementation was checked on macOS Tahoe 26.5.1 against both the public sharing APIs and the installed Mail and Messages share extensions.

- Mail and Messages advertise support for web URLs and text in their `NSExtensionActivationRule`.
- `NSSharingService.canPerform(withItems:)` returns `true` for a URL, a plain `String`, an `NSAttributedString`, and URL-plus-text combinations in both Mail and Messages.
- Both services return `false` for raw HTML `Data`.
- `ShareLink` offers a subject and message, but its public API does not promise that an activity will preserve arbitrary HTML or compose multiple exported representations into one rich body.

For that reason SwiftMiner does not send an HTML attachment or use Mail-specific behavior. Mail receives the invitation URL, subject, and plain message. Messages receives the URL and message and naturally ignores the email-only subject. Copy Link, AirDrop, and destinations that discard the optional fields still receive the complete SwiftMiner URL.

## Shared representations

1. The primary item is `https://swiftminer.app/setup/?from=<inviter>#invitation=<payload>`.
2. The native message contains the inviter, a credentials reassurance, and the 30-minute expiry without implementation details.
3. The native subject is `<inviter> invited you to SwiftMiner`.
4. The plain `message` is the portable fallback. Destinations that support contextual text combine it with the primary URL; destinations that discard it still keep the complete setup URL.
5. Link presentation is owned by the setup page's Open Graph and Twitter metadata.

The Twitch device code is encoded inside the URL fragment. Fragments are not sent to the GitHub Pages host or to link-preview crawlers. The setup page decodes it locally, validates the expiry, and opens Twitch's device authorization page with the code prefilled. No Twitch activation URL, device code, numbered instructions, Discord details, or dashboard details appear in the share message.

## Hosted preview behavior

The website deployment publishes the generic 1200×630 preview image at `https://swiftminer.app/assets/share/swiftminer-invitation.png` with no authentication; no invitation artwork is bundled or generated by the macOS app. The setup page references only absolute HTTPS asset URLs in its social metadata.

The page updates its document title and description metadata to name the inviter after decoding the invitation. SwiftMiner is currently hosted as a static GitHub Pages site, so crawlers that do not execute JavaScript receive the safe generic server-authored card (`Connect to SwiftMiner`) rather than inviter-specific text. A truly inviter-specific unfurled card would require a server or edge-rendered setup route; it cannot be produced by static Open Graph tags without exposing invitation data in pre-generated HTML.

This limitation does not affect the native Mail subject, the Mail/Message body, the browser page, expiry handling, or Twitch setup flow—all of those name the inviter dynamically.
