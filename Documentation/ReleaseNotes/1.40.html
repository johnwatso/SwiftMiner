SwiftMiner 1.40

Version 1.40 · Build 2026090209

Discord stops being a separate destination and becomes part of the miner it belongs to. Notifications that ask you to do something now link straight to the page where you can do it, and the app is clearer about the difference between a reward you cannot earn and one that simply cannot be delivered yet.

🐝 Fixes

  • Account-link reminders no longer disappear from the Needs Attention banner and the sidebar count while remaining in Pending. All three now apply the same rule, so a miner never looks healthy in one place and blocked in another.
  • A campaign whose drops are all claimed but whose game account is still unlinked is described correctly: the rewards cannot be delivered, rather than the drops cannot be earned.
  • Picture-source changes apply immediately across Settings, Miners and the web dashboard instead of waiting for the next daily refresh, and a temporary network failure no longer clears a working Twitch picture.

💬 Discord lives with its miner

  • The standalone Discord section has been removed from the sidebar. Everything it offered — linking, re-linking, unlinking, message history, resending, and sending a welcome message — now sits in a Discord section on the miner it belongs to, between the campaign queue and Status.
  • Collapsed, the section answers the only questions that usually matter: which account is linked, whether it is healthy, and how much history there is. Expanding it reveals the last DM, recent messages and the account controls.
  • Problems are distinguishable at a glance. A miner with no Discord account reads as not linked rather than as an error, while an unreachable bot, an account SwiftBot can no longer see, and a failed delivery each say so plainly.
  • Pending items report when their own reminder was last delivered, and say when automatic reminders are switched off so a silent reminder is never mistaken for a sent one.

🔗 Notifications that lead somewhere

  • Discord messages that ask you to act now carry a button to the exact page that resolves them — the account's connection, a named campaign, or your completed drops — instead of the dashboard front page.
  • The web dashboard understands links to a specific miner, campaign, account connection or drops list, and highlights what the message was about when you arrive.
  • Messages name the actual problem where SwiftMiner knows it, so a subscription requirement or a missing account link is stated outright rather than reported as something needing a look.
  • A reminder about drops you have already claimed says the rewards are waiting on the account link, instead of asking you to go and earn them again.
  • When no public dashboard URL is configured, messages carry no button at all rather than a link that cannot open.

📚 Help

  • A new guide covers drops that require a paid Twitch subscription: what the warning means, why watch time alone will never complete them, and what your options are.
