SwiftMiner 1.41.1

Version 1.41.1 · Build 2026091109

Three things a long diagnostic caught the fleet doing to no purpose: miners piling onto one stream despite stream spreading being on, every claim pausing on a Twitch call that has never once succeeded, and the Activity Log burying the useful lines under duplicates. A miner waiting for a stream now says which game it is waiting on, and inviting a friend through SwiftBot no longer offers the server’s bots as people to invite.

🐝 Bug fixes

  • Miners no longer pile onto one stream when several pick a channel at the same moment. Stream spreading asked which channels its siblings held, but a miner only counts as holding a channel once it has started watching — so when a campaign ended and several miners re-picked together, each of them read the same snapshot, each avoided the one stream that was genuinely taken, and all of them landed on the same free one. A miner now reserves its choice as it makes it, so the next miner to choose can already see it.
  • Claiming a drop is no longer followed by a request that cannot succeed. Every successful claim triggered a tidy-up call to remove the matching Twitch notification, and that call has been failing every single time — Twitch no longer recognises the query, and it was being given the wrong kind of identifier besides. It added several seconds to each claim while accomplishing nothing, and it failed quietly enough that only a diagnostic export showed it. The call is gone; claiming itself was never affected.
  • A miner waiting for a stream now names the game it is waiting for. A miner that is watching leads its card with the game, and so do the claiming and stream-override cards — but the waiting card led with its state and left the game to a single line of detail, which a compact card on Overview cuts short. Waiting is the state a fleet spends most of its time in, and it was the one card that never said what it was waiting for. It now names the game where the watching card does, with the campaign beneath it and the game’s artwork alongside, while the antenna symbol and the absent progress bar go on saying that nothing is being earned yet. The miner’s detail page, the sidebar and the status label name the game too.
  • The wording of that state is now the same everywhere it appears: “Waiting for an eligible live stream”, in place of “No eligible stream live” on the card and “Waiting — No live stream” in the status label.
  • Inviting a friend through SwiftBot no longer lists the server’s bots and webhooks as people you could invite. A recipient without a bot flag is still treated as a person, so a server whose member list predates the flag is unaffected.

🔍 A readable Activity Log

  • The line explaining which campaign a miner chose, and why, is written once per decision instead of several times a second. It was also being emitted by parts of the app that only wanted the campaign list in order to refresh the screen, and because each of those read a slightly different snapshot, neighbouring lines could disagree about how many campaigns were eligible. Over sixteen hours that was more than a thousand duplicate lines.
  • The viewer count of the stream being watched is recorded every five minutes rather than every ten seconds. It was a sixth of the whole log. It is kept at all because it is proof that Twitch’s live event feed is still delivering — a feed that fails silently is exactly the sort of thing these logs get read to find.
  • When Twitch’s edge returns an error page instead of an answer, the log records what went wrong in one line instead of pasting the entire fifteen-line page.
  • A diagnostic export now says when followed-streamer prioritisation is switched on but not actually working. Twitch can refuse to serve follow state for an account until it is signed in again; that was reported once, when it happened, and a report pulled hours later gave no sign the setting had been doing nothing all along.
