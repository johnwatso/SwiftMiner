SwiftMiner 1.41.1

Version 1.41.1 · Build 2026091211

SwiftMiner 1.41.1 makes a fleet easier to trust and operate: miners spread across streams as configured, claims no longer pause on a Twitch call that cannot succeed, and the Activity Log keeps the useful lines visible. Waiting cards identify their game, Game Rules are calmer to scan, and a new Advanced compatibility path can recover from future Twitch query-hash changes even without another SwiftMiner release.

🐝 Bug fixes

  • A campaign you have already finished can no longer come back as unmined. SwiftMiner reads claimed state from one place — the list of claimed benefits Twitch returns with your inventory — and treats it as the whole truth. When a response came back without that list, every earned drop read as unclaimed, so completed campaigns reappeared as available and the fleet spent its cycles hunting live streams for rewards already sitting in the inventory. Two things now prevent it: a reply that carries no claimed benefits where SwiftMiner already knew of some is treated as a degraded answer rather than an emptied inventory, and a discovered query hash whose reply arrives without that list is retired on the spot, the bundled one restored, and that value not offered again until the next explicit check. Transport success alone is no longer taken as proof that a hash returns something usable.
  • Miners no longer pile onto one stream when several pick a channel at the same moment. Stream spreading asked which channels its siblings held, but a miner only counts as holding a channel once it has started watching — so when a campaign ended and several miners re-picked together, each of them read the same snapshot, each avoided the one stream that was genuinely taken, and all of them landed on the same free one. A miner now reserves its choice as it makes it, so the next miner to choose can already see it.
  • Claiming a drop is no longer followed by a request that cannot succeed. Every successful claim triggered a tidy-up call to remove the matching Twitch notification, and that call has been failing every single time — Twitch no longer recognises the query, and it was being given the wrong kind of identifier besides. It added several seconds to each claim while accomplishing nothing, and it failed quietly enough that only a diagnostic export showed it. The call is gone; claiming itself was never affected.
  • Campaign discovery uses Twitch’s replacement Drops dashboard query, and temporary GraphQL timeouts now retry with bounded backoff. A cancelled or unavailable upstream request can no longer masquerade as an incompatible response and stop that mining cycle.
  • A miner waiting for a stream now names the game it is waiting for. A miner that is watching leads its card with the game, and so do the claiming and stream-override cards — but the waiting card led with its state and left the game to a single line of detail, which a compact card on Overview cuts short. Waiting is the state a fleet spends most of its time in, and it was the one card that never said what it was waiting for. It now names the game where the watching card does, with the campaign beneath it and the game’s artwork alongside, while the antenna symbol and the absent progress bar go on saying that nothing is being earned yet. The miner’s detail page, the sidebar and the status label name the game too.
  • The wording of that state is now the same everywhere it appears: “Waiting for an eligible live stream”, in place of “No eligible stream live” on the card and “Waiting — No live stream” in the status label.
  • Inviting a friend through SwiftBot no longer lists the server’s bots and webhooks as people you could invite. A recipient without a bot flag is still treated as a person, so a server whose member list predates the flag is unaffected.
  • The Overview toolbar no longer paints a blank white strip over the top of the dashboard in the Standard appearance.

🎨 A calmer Game Rules sheet

  • Each game rule now sits in its own compact, borderless card. The old run of horizontal separators is gone, leaving spacing and shape to distinguish games while keeping the artwork, rule picker, reorder handle, and fallback settings together.

🔍 A readable Activity Log

  • The line explaining which campaign a miner chose, and why, is written once per decision instead of several times a second. It was also being emitted by parts of the app that only wanted the campaign list in order to refresh the screen, and because each of those read a slightly different snapshot, neighbouring lines could disagree about how many campaigns were eligible. Over sixteen hours that was more than a thousand duplicate lines.
  • The viewer count of the stream being watched is recorded every five minutes rather than every ten seconds. It was a sixth of the whole log. It is kept at all because it is proof that Twitch’s live event feed is still delivering — a feed that fails silently is exactly the sort of thing these logs get read to find.
  • When Twitch’s edge returns an error page instead of an answer, the log records what went wrong in one line instead of pasting the entire fifteen-line page.
  • A diagnostic export now says when followed-streamer prioritisation is switched on but not actually working. Twitch can refuse to serve follow state for an account until it is signed in again; that was reported once, when it happened, and a report pulled hours later gave no sign the setting had been doing nothing all along.

🧰 Twitch compatibility that can outlive an app update (beta)

  • This one is marked beta in Settings. It is new, and the situation it exists for — Twitch retiring a query SwiftMiner depends on — happens every couple of months, so it will take a few of those to prove. Nothing it does can stop mining: the queries SwiftMiner ships with are never discarded, and anything it cannot confirm is thrown away rather than adopted.
  • Automatic Twitch Compatibility closes the gap that normally leaves a Twitch miner broken for days. When Twitch retires one of the queries SwiftMiner depends on, SwiftMiner notices that its own value has stopped working, opens the Twitch Drops pages in Safari so the extension can read the replacement Twitch itself moved to, tries it, and adopts it only if the reply carries what SwiftMiner actually reads. It checks at most once every half hour, says so in the Activity Log, and falls back to the version it shipped with if anything is wrong. The whole system can be switched off with a single toggle.
  • When Twitch retires a query outright, SwiftMiner can now send the query itself instead of waiting for a replacement value. A persisted query is only a reference to something Twitch stores; where SwiftMiner knows the query exactly it sends it inline and carries on, which is the difference between a miner that stops for days and one that does not notice. Claiming a drop is the first to work this way.
  • A query that still works is never touched, however different the value on Twitch’s own site is. Twitch serves more than one document under some operation names, and copying one of those over a healthy query is a way to break a miner rather than fix it.
  • Advanced Settings now reports that as a status board rather than a configuration screen. Each operation SwiftMiner depends on gets a row comparing what the app sends against what twitch.tv sends, with one headline above it: up to date, checking, update detected, updated automatically, waiting for Twitch, or an amber note that a change could not be verified. Nothing here is red — the bundled fallback means mining continues either way.
  • There is no longer a hash to read, copy or type. The manual override, its text field and its query picker are gone; raw values live under Technical Details alongside the last check, the last successful update and a manual re-check.
  • The extension now also watches Twitch’s category directory, not just the Drops pages. The game directory query is the one Twitch changes most: four of the eight rotations upstream recorded in the year to September 2026, more than every other query combined, and it stops mining outright. Watching only the Drops pages would have left the majority of real breakages uncovered.
  • The extension passes only an allow-listed operation name and its 64-character hash to SwiftMiner — never cookies, tokens, variables, or responses. That is unchanged; only the pages it watches have widened.
