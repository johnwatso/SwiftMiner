Release SwiftMiner 1.35

SwiftMiner 1.35 restores the Twitch drop claim and watch-progress paths,
rebuilds the Miners tab around a macOS Tahoe operator view, makes health and
campaign state more truthful, and substantially improves cold-launch and
artwork behaviour.

Drop claiming and claim history

- Read Twitch's current claimDropRewards mutation response while retaining
compatibility with the legacy claimDropBenefit field.
- Recognise Twitch's real successful and already-claimed statuses so retries
are idempotent rather than reported as failures.
- Surface GraphQL messages, explicit null claim payloads and unexpected reply
keys instead of collapsing response changes into a generic invalid-response
error.
- Confirm ambiguous claims across several spaced inventory reads because
Twitch's inventory can lag behind a successful mutation.
- Record every claimed reward in the earning ledger, scoped per account, so
claim totals, history, notifications, Discord events, drop state and Twitch
inbox cleanup all run correctly without double-counting retries.
- Invalidate cached pre-claim campaign details in memory and on disk as soon
as a claim succeeds.

Credited watch progress and reporting

- Send Twitch's complete current minute-watched beacon payload, including the
stream category, client timestamp, live state and watched-minute fields,
while preserving GraphQL heartbeat fallback.
- Show cumulative verified minutes across every timed drop in a campaign and
share the same live timer/progress calculation between Overview and Miners.
- Bring WebUI progress into parity with the app by reconciling Twitch's partial
inventory response with the miner's persisted ledger, using the correct
required-minute total and excluding zero-minute rewards.

Miners rebuilt for macOS Tahoe

- Replace the selected miner page with an operator-focused identity and health
header, Now / Next / Then summary, resolved campaign queue, compact subsystem
checks, priority controls and secondary recovery diagnostics.
- Introduce reusable Tahoe cards, raised surfaces, section treatments, row
dividers and adaptive buttons, with coherent fallbacks on older macOS.
- Restyle the miner source list with a soft selection pill, roomier grouped
sections, sentence-case headings and larger concentric corners.
- Add matching artwork for current and upcoming campaigns, larger queue
thumbnails and a responsive vertical fallback at narrow widths.
- Add selectable Discord or Twitch miner pictures under Settings > Appearance.
The other service is used as a fallback, then a local initial; resolved
pictures are cached for launch and the choice is included in settings backups.
- Remove completed campaigns from the queue. Prioritised games that still need
linking remain visible as actionable Needs setup rows, while unrelated
unlinked campaigns stay out of the queue.

Honest health and campaign visibility

- Report actual miner health -- healthy, idle, recovering, needs attention,
unresponsive, authentication required or blocked -- instead of repeating the
current campaign.
- Group uptime, last poll and health into equal-width responsive cells and
align subsystem status/timestamp columns.
- Reuse the status cluster on Overview with correctly scoped fleet averages and
a worst-state health summary instead of averaging categorical health states.
- Show Starting, Stopped and Updating at the correct times, plus honest waiting,
subscription and eligibility states.
- Keep prioritised campaigns visible in Drops for their whole active window,
even after their rewards are claimed, and count campaigns in motion from the
miners actually watching them.
- Keep prioritised artwork stable when returning to Overview rather than
replaying its placeholder transition.

Artwork reliability

- Request sharp 600x800 Twitch box art from both templated and fixed-size URLs
instead of stretching the default 120x160 image.
- Prefer Twitch artwork by default and reject Steam's successful-but-blank grey
placeholder images, including stale placeholders already cached on disk.
This restores real artwork for games such as THE FINALS and Battlefield 6.
- Restore prioritised Overview artwork from cached campaign data and share one
persistent artwork cache across Overview, Drops and miner details so images
survive relaunches and duplicate downloads are coalesced.
- Make Clear and Redownload Artwork invalidate the persistent image cache and
stale preference links as well as in-memory state.

Launch performance and efficiency

- Persist campaign details and account-link state with their original TTLs,
removing the cold-launch DropCampaignDetails fan-out for roughly 100 active
campaigns per account.
- Seed recent campaign and progress presentation from disk while the first live
refresh runs, without allowing cached data to make mining decisions.
- Keep campaign-detail files isolated when a Twitch client changes accounts and
preserve account-specific link and progress boundaries.
- Coalesce concurrent campaign refreshes for the same account and continue to
share safe campaign-global metadata across miners.
- Build off-screen miner sections lazily, resolve source-row snapshots once per
render, refresh minute-level uptime every 30 seconds and remove the scrolling
translucent header backdrop.
- Only resolve Discord display names for linked miners and detach that lookup so
an unavailable SwiftBot cannot delay the Miners tab.
- Centre animated refresh glyphs on their visible symbol so they rotate in
place rather than orbiting.

Website and help

- Refresh the Overview, Miners, Drops, Activity Log and Discord website captures
in light and dark mode, including an authentic five-miner fleet overview.
- Add light/dark screenshots for the main app, Game Rules and all Settings panes,
placing 36 contextual illustrations across all 20 help articles.
- Update screenshot dimensions, alternative text, README previews and the site
cache key so returning visitors receive the current images.
- Add a DEBUG-only multi-miner presentation fixture for genuine screenshots;
it is absent from Release builds.

Validation and release metadata

- Expand regression coverage for real claim responses, campaign ordering,
cumulative and WebUI progress, eligibility, startup states, persistent caches,
account isolation, avatar fallback and beacon payload parity.
- Pass the complete Xcode suite: 494 tests, 0 failures.
- Build successfully in Debug and universal Release configurations.
- Set MARKETING_VERSION to 1.35 and CURRENT_PROJECT_VERSION to 2026072814.
- Preserve the Sparkle feed URL and EdDSA public key; the ShipHook-owned appcast
remains on the currently published release until 1.35 is built and notarised.
