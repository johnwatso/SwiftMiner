Fix the 1.34.3 earning checks and stop refetching every campaign each cycle

Both halves of the 1.34.3 earning work were faulty, found by running it against
a real 22-hour session. Its ledger figures should not be trusted.

- Anchor the not-earning check on the last banked progress, falling back to
worker start. It measured from statusChangedAt, but mining cycles through
watching -> refreshing -> watching every few minutes, so the clock reset
before the threshold could ever be reached and the check never fired. Replayed
against the reported session, all five miners now flag correctly.
- Count earnings per drop from verified progress transitions instead of the
delta of an account-wide total. That total is a snapshot of drops in flight,
not a counter: it falls when a drop is claimed and jumps when a campaign
carrying existing progress rejoins the set, so the ledger both invented
progress and hid it. A drop crossing its requirement reports .claimable rather
than .progress, so both are counted or every drop's closing minutes are lost.
The same signal now drives lastDropProgressAt, so the health check and the
ledger cannot disagree, and earningReferenceDate is defined once instead of
being duplicated at three call sites.
- Give not-earning its own incident kind that records and displays but does not
notify. It can flag every miner at once, and its false-positive rate is still
unmeasured because the data needed to judge it was the ledger. The supervisor's
progressStalled alert is a different fault and still notifies.
- Raise campaignDetailsCacheTTL above the campaign check interval. Both were
exactly 5 minutes, so entries expired moments before each refresh asked for
them and nothing was ever served from cache: ~154k DropCampaignDetails calls
in 22 hours. Per-drop claim and progress state is owned by the inventory
snapshot, not this cache, so a longer TTL does not stale it.
- Let unlinked campaigns use the cross-miner metadata cache by remembering each
account's link state from its own real fetches. The previous gate existed
because link state resolves as details || basic, and serving shared metadata
would have dropped the details half, silently marking linked campaigns
unlinked and removing them from mining. Together roughly 20x fewer requests.

Set MARKETING_VERSION to 1.34.4 with build 2026072516 in project.yml and the
generated project, and publish matching release notes. The stable Sparkle
appcast is left to the release pipeline.
