Detect miners that watch without earning and record an earning ledger

Health monitoring only measured liveness: polls, events, worker state. A miner
could sit in .watching for hours earning nothing while every signal stayed
green, which is exactly what happened in the incident behind 1.34.1.

- Track lastDropProgressAt separately from liveness through the supervisor and
ManagedMiner, fed by the progress handler's already-computed rising metric.
- Flag a miner watching for 20 minutes without banked progress: a stall signal,
attention health, a "Watching - Not Earning" label, and a progressStalled
incident. Stream overrides are exempt and a fresh watch session is measured
from when it started watching. Evaluated on supervisor snapshots and written
only on a threshold crossing, since this failure never changes status and the
status-change path would never fire for it.
- Add EarningLedgerStore: hourly per-miner watch seconds, earned drop minutes
and claims, kept 7 days, throttled to a write a minute and flushed on hour
rollover and quit. Watch time samples off existing supervisor snapshots in
15s chunks rather than a new timer; earned minutes come from cumulative
totals as deltas with the first observation as a baseline.
- Surface it in Settings > Advanced > Diagnostics and in the diagnostic report,
which gains earning totals, non-earning hours, 48h of hourly detail, plus
lastDropProgressAt and the not-earning flag per miner.
- Implement MinerEngine.getRecentActivityEvents, which returned an empty array
and left the miner Recovery Timeline permanently blank in the app and the
Discord/web projection.
- Fix the README platform badge, which advertised macOS 26+ against a macOS 14
deployment target.

Set MARKETING_VERSION to 1.34.3 with build 2026072413 in project.yml and the
generated project, and publish matching release notes. The stable Sparkle
appcast is left to the release pipeline.
