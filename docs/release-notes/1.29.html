SwiftMiner 1.29

Version 1.29 · Build 2026061909

A web-dashboard and Drops polish release for checking and managing miners from the browser, with safer sign-in, clearer update controls, SwiftBot Patchy campaign announcements, and better visibility into each miner's priority and claimed-but-unlinked reward state.

🌐 Web Dashboard

SwiftMiner can now expose a browser dashboard when configured.

  • Adds an optional web dashboard for browser-based miner visibility.
  • Adds a local operator view for checking the whole miner fleet from the local network.
  • Adds a Discord-user view that is scoped to the signed-in user's own mined Twitch account.
  • Adds an Up Next campaign browser with box art, start/end timing, issue buttons, and one-tap prioritising for linked miners.
  • Adds polished web sign-in assets, app icons, favicons, timing refinements, and dashboard loading fixes.
  • Keeps the normal progress/status card separate from diagnostics, so idle miners still show Idle - no campaigns while deeper health details stay tucked away until requested.
  • Adds a Diagnostics toggle for operator triage, hiding stall confidence and recent health signals by default while preserving quick access when troubleshooting.
  • Adds a small sign-in easter egg: pressing F while the missed Drops respect line is shown sends salute emojis floating behind the login card.

📣SwiftBot Patchy Announcements

New Twitch Drops campaigns can now flow into Patchy-powered Discord announcements.

  • Emits SwiftMiner campaign events when new Twitch Drops campaigns are discovered while SwiftBot integration is enabled.
  • Includes campaign and game metadata, game artwork, and up to three drop reward images so SwiftBot can build rich announcement embeds.
  • Dedupe-protects campaign announcement events by campaign ID, preventing repeated Discord posts for the same discovered campaign.

🔐 Sign-In & Linking

Browser sessions are narrower, more auditable, and easier to complete.

  • Adds SwiftBot-backed Discord sign-in with signed assertions, replay protection, and normal dashboard sessions after handoff.
  • Adds local username/password sign-in that is only offered from local requests, keeping operator access off the public dashboard domain.
  • Adds Twitch sign-in scoped to the user's own mined account.
  • Restores self-service Twitch linking for Discord web sessions with a device-code card, activation polling, and automatic dashboard refresh once linking completes.
  • Auto-registers the SwiftMiner dashboard hostname with SwiftBot's tunnel when the integration can provide tunnel details.
  • Adds web sign-in, sign-out, blocked-attempt, and session audit events to the Activity Log.

🔄 Updates

Sparkle update behaviour is easier to inspect and control.

  • Adds update events to the Activity Log so checks, available updates, installs, and failures are easier to trace.
  • Adds settings for automatic update checks and unattended install options when macOS allows them.
  • Improves update settings with clearer state, manual actions, and fallback messaging.
  • Updates SwiftMiner build metadata to 2026061909 while leaving ShipHook-owned appcasts untouched.

⛏️ Miners & Campaigns

The Miners tab and campaign cards now explain priority and linking state more directly.

  • Adds a dedicated Priorities section to each miner showing personal games first and the global list behind them.
  • Adds a per-miner Use global priorities toggle, with running miners refreshed after priority changes.
  • Allows personal priorities to stand on their own when a miner opts out of global priorities, even if the same game is also global.
  • Shows claimed-but-unlinked campaigns as completed with a distinct question-badge status, so users know the drop is claimed but the game still needs linking.
  • Fixes completed campaign timing in the web projection so active-but-already-claimed campaigns no longer look like they completed one minute ago forever.
  • Removes the unused miner detail panel so the Miners tab is the single source of truth for priority, streamer, campaign, controls, and log UI.

🎮 Drops View

Claimed-but-unlinked rewards are clearer, and opening Drops feels steadier.

  • Clarifies Drops campaign cards so pre-claim unlinked games no longer appear as a separate actionable setup state; claimed rewards that still need the game linked now show as Claimed · not linked.
  • Uses a green claimed check with an orange question badge for claimed-but-unlinked miner states, making the reward state and missing game link visible at the same time.
  • Preloads the Drops view from the last known campaign feed during launch so opening Drops is less likely to show an empty placeholder while fresh Twitch data syncs.
  • Adds a polished Drops loading splash with an animated SF Symbol for first-load campaign syncs.
  • Removes the small per-reward progress strips from grouped Drops cards for a cleaner reward shelf.

🛡️ Safety & Polish

Public routes and embedded dashboard scripts now have tighter guardrails.

  • Tightens public route matching so only intended dashboard paths bypass the Bot-key API gate.
  • Adds regression coverage for local sign-in, session cookies, CSRF handling, Discord dashboard sign-in, dashboard route exposure, and web activation flows.
  • Adds JavaScript syntax coverage for emitted dashboard scripts to prevent broken web UI bundles from shipping.
  • Modernizes the Add Twitch Account login sheet with a cleaner two-step approval flow, stronger code presentation, copy feedback, and clearer waiting, success, and retry states.
